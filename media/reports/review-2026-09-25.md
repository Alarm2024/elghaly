**Write requests the "read-only" proxy forwards.** Tested locally with a copy of the repo and a fake upstream that records what it receives (Go 1.25):

| Request body sent to `stale serve` | Forwarded upstream? | Why | Is it a write? |
|---|---|---|---|
| `{"method":"sendBundle",…}` | **YES**, HTTP 200 relayed | Not on the two-name deny-list (serve.go:165–171). | Yes, on Jito-enabled upstreams (bundle submission). The same applies to any provider-specific send method not on the list. |
| `{"method":"sendTransaction","METHOD":"getSlot",…}` | **YES** | Go `encoding/json` matches field names case-insensitively and keeps the last match, so stale reads `getSlot` (serve.go:153–163). The original bytes are forwarded unchanged (serve.go:122). A case-sensitive upstream parser reads `method = sendTransaction`. | Yes: sendTransaction is smuggled past the filter. Whether a given provider then executes it is **UNVERIFIED** (not tested live, because that would be a write). |
| `{"method":"sendTransaction","method":"getSlot",…}` | **YES** | Duplicate key: stale takes the last one. | Only a write if the upstream keeps the *first* duplicate. UNVERIFIED per provider. |
| `[{"method":"sendTransaction",…}]` (batch) | No (400) | Array fails struct decode. | Refused. |
| `{"method":"send\u0054ransaction",…}` | No (refused) | The escape decodes to the canonical name. | Refused. |
| `{"method":"simulateTransaction",…}` | Yes | Not on the list. | Not a write. OK. |

**Section 2 verdict:** three of the four Limits lines match the code. The read-only line does not. stale **does forward writes**: (1) `sendBundle`, and any write-type method other than the two named, is forwarded as-is (confirmed); (2) `sendTransaction` can be smuggled with a case-variant duplicate `method` key, which stale forwards (confirmed) while reading it as `getSlot`. Whether the upstream executes (2) depends on its JSON parser and is UNVERIFIED. The live root page also hides the Limits (S1).
